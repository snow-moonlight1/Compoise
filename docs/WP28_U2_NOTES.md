## 行为与持久化

- “已了解旧密钥不能搬迁”与“当前安全存储仍需重配”是两个独立状态。启动页明确确认后，只有 Store 成功打开、没有恢复锁/凭据校验错误，才能把说明已读与整库一起提交；关闭或提交失败不消耗提示。
- 已读用户下次进入任务界面，未配置状态仍在 AI 设置页说明。只有当前保护存储写入并读回相同的非空密钥才清除重配状态；已有密钥的一次读取不算重新配置。已验证删除恢复重配状态，但不重新阻断启动。
- 普通提交失败保持未保存修订；已读提交失败回滚该决定。显式凭据导入与状态参加同一事务，失败恢复凭据与旧状态；后来的凭据意图不能被较早异步操作覆盖。
- 槽中两个可选字段只接受 `"true"`/`"false"`，优先于兼容布尔镜像。没有升级状态的库不增加字段。它们是本机状态，不进入备份 v3；详细规则见 [数据兼容性](DATA_COMPATIBILITY.md)。旧目录与加密文件始终只读，身份字段保持 Compoise/Compoise。

## 原生退出修复与诊断隔离

U1 首次启动报告曾成功，但退出超时。U2 在正常 Windows runner 中明确销毁派生窗口/Flutter 引擎，再调用 `CoUninitialize`。失败创建窗口同样先清理；派生析构调用 `Destroy`，避免基类析构无法分派派生 `OnDestroy`。正常应用的保存、单实例与激活接线继续沿用原实现。

诊断必须同时启用 C++ 环境门与 Dart 编译门；仅有一个时构建拒绝。诊断单实例使用本次 GUID 命名空间，资料根只接受 OS 临时目录中的规范路径 `wp28-u2-device-<GUID>`，正常包无法通过环境变量启用这些注入。实际入口仍是 `lib/main.dart`，渲染真实应用和恢复页面，以内部事件执行合成操作并保存页面图；不驱动用户鼠标、键盘或既有应用。

脚本仅跟踪本次启动的进程、路径和开始时间，记录退出码、超时及残留；强制清理不能把超时算通过。没有尝试操作 U1 留下的不可验证旧 PID 54968。调试输出不含用户路径、库内容或密钥。

## 可复现命令

固定 Flutter 3.32.8 / Dart 3.8.1。

```powershell
# 诊断 Release：只有同时提供两个门才可运行隔离 harness
$env:WP28_U2_HARNESS_BUILD = '1'
flutter build windows --release --no-pub --dart-define=WP28_U2_HARNESS=true -t lib/main.dart
powershell -NoProfile -File scripts/wp28_u2_windows_harness.ps1 -Configuration Release

# 验收后重建正常包，避免把隔离诊断包当作体验包
Remove-Item Env:WP28_U2_HARNESS_BUILD
flutter build windows --release --no-pub -t lib/main.dart

flutter analyze --no-pub
flutter test --no-pub
flutter test --no-pub test/wp28_u2_credentials_test.dart
```
