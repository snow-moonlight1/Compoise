## 1. 已确认的实现与用户现象

截图里的“无控件/有控件”与用户口中的“普通/编辑”不能直接当作内部模式名。按当前代码与截图对应关系，蓝色层叠图标、无编辑按钮的一屏很可能是 `_selecting=true`；灰色图标、有编辑按钮的一屏是 `_selecting=false`。这里的对应关系是静态推断，实施时用一组假任务在设备上确认，不要求用户重新解释模式名。

| 发现 | 源码事实 | 对现象的解释与证据限度 |
|---|---|---|

## 2. 三种状态必须分开

取消全局“编辑模式”这个概念。普通浏览里就能完成、查看子项、打开详情；只有“多选”是明确的临时模式。

| 动作 | 普通浏览 | 多选模式 | 是否保存到待办数据 |
|---|---|---|---|
| 点任务完成方框 | 切换 completed | 仍只切换 completed，不充当选择器 | 是，统一完成命令 |
| 点标题/任务正文 | 打开任务详情 | 切换是否选中，顶部明确显示“多选任务 · 已选 N 项” | 否，selectedIds 为会话状态 |
| 点“子任务 1/3 ▾” | 展开/收起 | 同样可展开/收起，不选择、不完成 | 否，展开为 UI 状态 |
| 长按正文并移动 | 跨象限拖动 | 已选任务发起集合拖动（WP10） | 只有成功落点才保存 |
| 轻滑 | 滚动 | 滚动 | 否 |
| 退出多选/切 board | 回普通浏览 | 清理本次选择；完成与展开状态独立 | 不改变 completed |

多选用**整行浅色高亮 + 明确的“已选”标记/数量**表达，不把原完成方框替换为第二种语义。多选标题区与完成方框事件不能冒泡串触；读屏分别说“标记任务完成”和“选择任务用于批量操作”。当隐藏已完成使一个已选任务离开可见列表时，清理对应 selectedId，数量更新，不触发批量命令。

完成方框、逐行删除线、淡化、隐藏过滤和归档页必须全部读取同一 `task.completed`。子项从 `sub.completed` 读取；父子级联继续使用已验收设置。不要为“修复同步”在切模式时覆盖 completed。

子项折叠后也必须留“子任务 已完成数/总数”入口。第一版默认收起；用户展开后，按 boardId/taskId 保存本会话状态，切模式不重置，重排按 ID 保留。新增子项后自动展开所属任务。展开列表保留全部子项及完成状态；全局 hideCompleted 先沿用主任务过滤，不偷偷把子项数与展开内容变成不同口径。

## 3. 布局定案：一个十字，轻量任务行，编辑移到详情

### 矩阵主体

- 采用用户提出的十字：同一张背景上仅一条竖分隔线与一条横分隔线，四个区域内独立滚动；不再给每个象限套圆角盒子，也不给每条待办套白色浮起卡片。滚动边界与中央分隔固定，不随某条长任务移动。
- Q1 左上、Q2 右上、Q3 左下、Q4 右下；这保持现有 q=1/2/3/4 数据含义。横向左“紧急”、右“不紧急”，纵向上“重要”、下“不重要”；不要因为查到另一种坐标布局而交换历史任务的象限编号。
- 四个标题完整表达维度，允许两行：**紧急且重要 / 不紧急但重要 / 紧急但不重要 / 不紧急也不重要**。可将“紧急/不紧急”设为第一行，“且/但重要”等为第二行；Semantics/aria-label 始终为完整名称。不能以截断省略号把“不”隐藏。
- 用现有象限颜色做小圆点/标题强调，不整块铺深色，也不靠颜色单独表达重要性。计数弱化为标题旁纯文本，清空收进主界面菜单，释放标题宽度。
- 手机操作栏保留 board、视图/多选、设置；“新增”放矩阵外的底部安全区，不浮在 Q4 最后一条上。只有实际拖入/选中时显示局部浅色反馈，没有常驻选择边框。

### 窄任务行

- 左边是约 20–22 dp 的完成图形，点击区域至少 48×48 dp；右边正文首行对齐，字重约 500、基准 16 sp、行高约 1.4。视觉图形小不意味着触摸面积小，按钮热区不能覆盖标题或相邻行。
- 标题在矩阵中最多显示 3 行；更多内容到全宽详情阅读，不能为了塞下标题把字缩成小号。无子项/日期时不留空的元数据行；有子项时显示明确的展开入口，日期放在正文下的次级行，不占正文右侧一列。
- 390 dp 只是设计测试宽度，不能从图片像素直接推断手机 dp。按左右 8 dp、中央 1 dp、每半区内边距合计 16 dp、完成热区 48 dp 估算，标题仍只有约 122 dp，16 sp 中文大约 7–8 字一行。**去框能减少浪费，不能让半屏获得全屏宽度。** 因此保留全宽列表模式，并允许点象限标题进入该象限的全宽列表，返回恢复滚动位置。
- 默认矩阵作为总览，用户自选列表作为日常执行页，记住选择。大字号下优先换行或使用全宽视图，不禁用系统字号，也不自动反复替用户切视图。

结构示意（示意宽度不是最终像素稿）：

```text
我的任务 ▾                          多选  设置

紧急且重要       2 │ 不紧急但重要       1
                   │
□ 准备本周项目汇报 │ □ 整理下季度学习计划
  今天截止         │   子任务 1/3 ▾
                   │
□ 确认活动场地     │   □ 列出学习主题
                   │   ☑ 整理参考资料
───────────────────┼───────────────────
紧急但不重要     1 │ 不紧急也不重要     1
                   │
□ 回复活动时间     │ □ 整理收藏夹
                   │

＋ 添加待办                       矩阵 / 列表
```

### 编辑和批量控件放哪里

- **手机**：点标题打开全宽任务详情底部面板，可上拉到接近全屏。标题多行编辑、截止日期、象限、子任务、长期标记、AI 拆解、删除放在该面板内；不再给每一条任务常驻旗子/铅笔/垃圾桶/添加子项整行。
- **Windows/宽屏 Web**：可用宽度足够时，右边显示 320–360 dp 详情栏，左侧矩阵至少保留约 560 dp；不满足时改用全宽面板。根据实际窗口宽度决定，不能依据“桌面系统”标签强塞侧栏。
- **多选**：底部安全区换成一条上下文工具栏：“已选 N 项 / 移动 / 更多 / 退出”。编组、批量日期、删除放“更多”内；删除继续确认。选中 0 项时保留提示且命令禁用，不把大量操作按钮重新铺回每条任务。
- 完成、展开、拖动均不需要打开详情。批量模式点击正文为选择，可通过工具栏单项“详情”打开；不使用同一个长按同时执行“选择”和“拖动”。
- 关闭详情不提交未保存文字；保存/取消含义明确。返回键先收键盘，再退详情，再退出多选，最后才离开应用；焦点回原任务。详情被关闭或目标任务删除时，在途请求不得重新创建旧任务。

### 视觉起点与自检

沿用现有主题色与系统中英日字体，减少装饰而非重新做品牌；浅色背景建议 `#F7F8FA`，正文 `#242A32`，次级字 `#596370`，十字线 `#D5DAE1`，选中反馈 `#E6EEFF`。深色使用现有 ThemeData 的 surface/onSurface/outline，不硬套浅色值。标题与正文可共用系统字体，靠层级和字重区分，避免新增网络字体依赖。这是与四象限结构相配的候选 token，实施时验证对比度。

自检结论：仅“取消边框”仍解决不了多行标题和满屏编辑控件；必须同时做行内对齐、操作移出、详情全宽。反过来，全部控件藏进菜单又会让子任务不可发现，所以完成与子任务展开继续留在矩阵中。

## 4. 截止日期与紧急性的规则

1. **普通/AI 新增都提供可选日期**：“截止日期 · 未设置”，点开有今天、明天、选择日期、清除。批量新增的公共日期清楚注明“应用到本次新增任务”；只作用于主任务，子任务不会无提示继承。AI 请求提交时捕获该日期，与目标 board 一起随结果应用，不读取请求完成时已经改变的表单日期。
2. **父子详情同一种编辑器**：标题、截止日期、清除日期、保存/取消可达；父日期不静默覆写子日期。批量改日期只改变显式选中的对象；子日期晚于父日期可提示但不擅自改值。
3. **清楚命名**：把“紧急阈值”说明为“临近截止日期时自动转为紧急”，显示“提前 N 天（含当天）”。例：N=3 时，9 月 8 日到 9 月 11 日截止的未完成主任务进入紧急列。过期仍算紧急；无日期不参与。不是提醒通知，不是自动完成，也不是计划开始时间。
4. **同一日期判断**：标签、着色和移动共享日历天函数，避免硬编码 2 天与设置 N 天不一致。重要性保持不变，只允许自动 Q2→Q1、Q4→Q3，不自动降级。第一版子项截止单独展示，自动象限升级只依据主任务截止，说明文字要写明范围。
5. **人工优先（WP22-C，依赖数据兼容包）**：显式手动改变紧急/不紧急维度后，将该任务标为手动紧急性；后台不立即搬回。详情提供“按截止日期自动调整紧急性”开关可恢复自动。仅修改重要/不重要维度不改变该开关；编辑日期不会偷偷解除手动选择。新增任务及旧数据保持已有自动模式缺省。这需要持久化小字段，不能仅用会话变量假装重启后仍有效。
6. 保留 deadline 与计划日/日程的区别；新建日期功能不等待 Planner。日期只选择天时，不制造“今天凌晨已过期”的文案，也不许 AI 无依据补造用户未设置的期限。

## 8. 实施前后最小验收矩阵

- 普通/多选 × 完成/未完成 × 有/无子项 × hideCompleted 开/关；验证方框、逐行删除线、过滤和存储一致。
- 按用户顺序：完成一父任务→切多选→退出→隐藏/显示已完成→重启；以及只选择一任务→隐藏已完成→退出；两条路径必须不同且可理解。
- 展开子项→切模式→改父/子完成→切板回来→拖动重排，展开入口始终可达；删除任务不复活 UI 状态。
- 360/390/412 dp、长中文 3+ 行、英语长单词、日语、字号 1.0/1.3/2.0；检查首行对齐、点击热区、文本截断可到详情读全、中央十字、底部工具栏不覆盖任务。
- 新建普通/AI/批量都可选日期；父/子日期编辑与清除；今天/昨天/N/N+1、夏令时跨日、前后台/午夜刷新、手动调象限不回跳。
- 复用旧 66 项测试中有价值的场景，并新增上述真实缺口；修改了交互契约的旧断言需说明为什么更新，不能为“全绿”删除用例。
