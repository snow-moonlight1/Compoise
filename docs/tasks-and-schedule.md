# 任务与日程

本文说明任务、子项、截止与提醒、今天待办和日程的规则。字段的具体格式见[备份格式](backup-format.md)。

## 任务和子项

- 任务属于某个任务板，在四个象限之一（1 重要且紧急、2 重要不紧急、3 紧急不重要、4 都不）。
- 任务可以有子项（步骤）。子项有自己的完成状态、截止时间、提醒和笔记，但没有象限和标签。
- 标签只属于父任务。读入时会去掉首尾空格和空标签，大小写不同的重复标签只保留第一个。多个标签筛选时取交集。
- 笔记是纯文本，父任务和子项都可以有。

### 输入

- 新建时默认是一行可勾选的输入框。按回车会增加下一行；只写了一行就保存成普通任务，写了两行以上就保存成一个父任务加若干子项。父任务标题没填时，用第一行生成一个可以修改的标题。
- 想一次新建多条独立任务，请用“批量新建”。
- 中文、日文输入法确认候选词时，不会新增行，也不会保存。
- “截止与提醒”中分别选择截止和提醒的日期、时刻。只改其中一项，另一项不会跟着变；取消任何一个选择器，不应用半个结果。

## 截止时间和提醒

- 截止时间 `deadline` 保存用户选择的具体时刻（Unix 毫秒），提醒时间 `reminderAt` 独立保存。新建任务、父任务和子项编辑使用同一套日期与时间选择器，精确到分钟。
- 不再提供“今天／明天”截止日期和固定提醒预设。保存未修改的任务时，保留原有时刻，包括导入数据里的秒和毫秒。
- 子项的截止时刻晚于父任务时显示提示，同一天里的时刻也会比较。
- 计划日功能已移除。旧文件中的 `plannedDate` 仅保留原值用于保存和备份往返，不出现在界面中，也不参与今天待办、日程或紧急性判断；存储键和备份格式没有改名。

### 紧急阈值

- `lib/deadline_policy.dart` 以本地日历天计算距离截止日期的天数，包含阈值当天。阈值为 1 天时，明天截止的自动模式任务立即进入紧急象限，无需再等 24 小时。
- 自动模式下，Q2 → Q1、Q4 → Q3，重要性不变。已完成、没有截止时间和手动模式的任务跳过；仅提升紧急性，不自动反向降级。
- 启动、回到前台、编辑截止、修改阈值或恢复自动模式时立即检查；保持应用打开时每小时检查一次。
- `test/urgency_clock_audit_test.dart` 用注入时钟和组件测试的模拟时间验证启动、跨日定时检查、前台恢复、阈值变更及保存重载，不修改系统时钟，也不需要等待真实的一天。

## 今天待办

今天页按日期汇总，不按象限分组：

1. **今天日程**：当天时间线关联的任务。
2. **今天到期或已过期**：截止日期是今天或已过，且不在上一组。

- 一个任务只显示一次，不改写任务的截止时间、提醒或象限。组内按截止最近、创建最早排列。
- 日程按设备当前时区判断是否占用今天，跨天日程也会纳入；恰好在今天零点结束的不纳入。移动或删除日程后即时更新。
- 每行显示任务所属象限。跨任务板查看，或者任务不在当前任务板时，显示任务板标记。
- 完成操作立即保存；该行先播放共 0.4 秒的逐行划线，再用现有离场动画移走，最后显示当天全部完成反馈。开启减少动画时直接更新。

## 日程

日程页（`lib/planner/`）和任务页是同级的两个页面，顶部用“任务｜日程”切换。日程页有日视图和周视图，下方是当前任务板的任务池。

### 两种日程

| 种类 | 必填 | 说明 |
| --- | --- | --- |
| 时间块 `timeBlock` | `taskId`、起止时间、时区 | 给某个父任务预留的工作时间。标题、任务板和完成状态都跟随任务。一个任务可以有多个时间块。 |
| 日程事件 `event` | 标题、起止时间、时区，以及 `taskId` 和 `boardId` 二选一 | 有自己标题的事项，比如会议。可以关联一个父任务；不关联任务时必须指定任务板。 |

- 日程有自己的 ID，不和任务 ID 混用。日程只能关联父任务，不能关联子项。
- 设置日程不会改变任务的截止时间或提醒，反过来也一样。

### 时间与时区

- 起止时间按绝对时刻保存（Unix 毫秒），同时记录创建或最后编辑时的 IANA 时区。
- 视图按设备当前时区显示。切换设备时区只改变显示，不改写已保存的记录。
- 跨天的日程在每一天显示一段，点击任何一段都是编辑同一条日程。恰好在零点结束的日程不占用第二天。
- 夏令时跳过的时刻不存在，编辑器会提示重新选择。夏令时重复的时刻，自动取较早的那一次。
- 允许日程互相重叠。重叠的日程并排显示，每条都能点到。

### 编辑

- 拖动日程按 15 分钟吸附，拖动时整体保持原有时长；拖上下边缘可以调整开始或结束时间。日程不能拖过当天的 0:00 或 24:00。
- 从任务池把任务拖到时间线上，就会建立一个时间块。
- 删除日程前会先确认。删除日程不影响任务。
- 删除父任务时，会同时删除它的所有时间块和关联事件；删除任务板时，会删除板上的任务、这些任务的日程，以及这个板上的独立事件。
- 保存时会检查是否有冲突的编辑，同一条日程不会被后到的旧数据悄悄覆盖。

### 引导

第一次进入日程页时显示一组简短的引导，可以跳过，也可以在设置或日程页菜单里再次打开。是否看过引导保存在本机的独立键里，不随备份转移。

## Android 提醒设置

- 首次完成应用引导后，在单独页面提供可跳过的提醒设置。点“开启提醒”后，只申请尚未开启的通知、准时提醒和后台运行，按顺序进行；拒绝其中一项时停止后续申请。
- 系统设置返回后刷新真实权限状态，并重新安排已有的未来提醒。用户已开启的权限不重复申请。
- 自启动仅在能找到厂商入口时提供快捷跳转，不显示“已开启”等无法核实的状态。入口失效时尝试应用设置；旧手机设置说明保留在可展开区域。
- 设置中的“提醒与后台设置”随时可以重新打开。Windows 和 Linux 不进入手机权限引导。
- 使用 Android 官方通知、精确闹钟和电池优化接口，厂商自启动入口参考 [autostart_settings 的实现](https://github.com/chris-wolf/autostart_settings)。系统行为参考 [Android 闹钟文档](https://developer.android.com/develop/background-work/services/alarms)和 [Doze 文档](https://developer.android.com/training/monitoring-device-state/doze-standby)。没有加入常驻服务或轮询保活。
