# 实施计划（v1.0 之后）

本文是 [路线图](roadmap.md) 的展开版：说明 v1.0.0 之后先做什么、每一项具体改哪里、怎样算做完。路线图只列方向；这里写到可以直接拆成 issue 的粒度。

> 原计划基于 `3f7d371`（v1.0.0）；2026-10-19 已按维护者决定调整 v1.1.0 范围，并更新实现现状。v1.1.0 发布后，维护者决定把可选同步提前到 v1.2.0，原“数据安全与规模”顺延到 v1.5.0，新增 v1.3.0（月视图与 AI 指令）和 v1.4.0（桌面小组件与 AI 排程）。规模估算按一名维护者计：S ≈ 1–2 天，M ≈ 3–5 天，L ≈ 1–2 周。实际排期以 GitHub Milestone 为准。

## 1. 原则

做取舍时按这几条判断，排在前面的优先：

1. **数据不丢**：任何新功能都不能削弱现有的双槽提交、启动恢复和导入预检。宁可拒绝导入，也不悄悄丢字段。
2. **本地优先**：不引入方寸自己的账号，不做自己的服务器。需要联网的功能（检查更新、同步）必须由用户主动开启，默认关闭；同步只连接用户自己的网盘或文件夹。
3. **先补维护手段，再加功能**：发布之后最缺的是“出了问题怎么知道、怎么修、怎么让用户拿到修复”。
4. **小步发布**：每个版本只带一两个主要功能，其余是修复。
5. **改到哪儿顺手整理到哪儿**：结构性重构跟着功能做，不单独停下来做大重写。

## 4. v1.0.1：稳定与维护

状态：v1.0.1 已于 2026-10-19 发布，仓库与发布防护、诊断、可选更新检查和 AI 超时已落实。

目标：让问题能被发现、能被报告、修复能送到用户手里。不加新功能。

### 4.1 仓库与发布防护（S）

- **保护 `main`**：要求通过 `PR checks` 的 `Analyze and default tests` 和 `Android debug APK` 两个 job 才能合并；禁止强制推送。
- **构建号必须递增**：在 `release.yml` 的 preflight 中，读取上一个正式 Release 的 `RELEASE_METADATA.txt`（或上一个 `v*` 标签处的 `pubspec.yaml`），新 `+N` 不大于旧值时直接失败。同时更新 `scripts/tests/` 中的回归测试和[发布流程](release-process.md)。
- **本地签名材料**：维护者本机的 `Android credential/` 目录未被忽略，把它加入 `.gitignore`（或移出仓库），避免 `git add -A` 误提交。
- **仓库信息**：GitHub 描述补上 Linux；开启 Discussions；建立标签（`bug`、`enhancement`、`good first issue`、`translation`、`platform:android/windows/linux`）。

完成标准：在 fork 或测试仓库里推送一个构建号没有增加的正式格式标签，preflight 失败并给出明确提示；`-ci` 标签不受影响。

### 4.2 诊断日志与“导出诊断信息”（M）

- 新增 `lib/diagnostics/app_log.dart`：本地滚动日志（例如单文件 512 KB，保留 3 个），写入应用数据目录。只记录事件类型、错误类别和时间，**不记录任务文字、笔记、API 密钥、请求正文**。
- 把 `reminder_service.dart` 的 16 处、`desktop_shell_windows.dart` 的 2 处 `debugPrint` 改为写日志；在 `FlutterError.onError` 和 `PlatformDispatcher.instance.onError` 记录未捕获异常。
- 设置 → 关于：新增“导出诊断信息”，打包日志 + 版本号 + 平台 + 设置摘要（不含任务内容），让用户自己附到 issue。
- `bug_report.yml` 增加一项“诊断信息（可选）”。
- 更新[隐私说明](privacy-policy.md)：日志只在本机，只在用户导出时离开设备。

完成标准：单元测试覆盖日志脱敏（构造含任务标题和密钥的异常，导出内容里查不到）和滚动上限。

### 4.3 检查更新（S–M）

- 设置里新增“检查更新”开关，**默认关闭**；开启后每天最多请求一次 `https://api.github.com/repos/snow-moonlight1/Compoise/releases/latest`，比较语义化版本，有新版时显示一条不打扰的提示和 Release 链接。
- 不自动下载，不自动安装；请求失败静默忽略并写日志。
- 设置页另有“立即检查”按钮，不受开关限制。
- 隐私说明补充：开启后会向 GitHub 发送一次不含个人数据的请求。

完成标准：用假 HTTP 客户端测试版本比较（含 `-ci`、`+N`）、无网络、限流（HTTP 403）三种情况。

### 4.4 AI 请求超时可调（S）

- `aiRequestTimeout` 目前固定为 30 秒，推理型模型拆解复杂任务时容易超时。改为在 AI 设置里可选 30 / 60 / 120 秒，默认 60 秒；“测试连接”仍用短超时。
- 超时提示里说明可以调长超时或换非推理模型。
- 流式输出放到以后再评估，本版本不做。

### 4.5 文档修正（S）

- `docs/README.md` 中“任务与日程”一行仍写着“计划日”，该功能已在 #17 移除，改掉。
- `roadmap.md` 改为指向本文，保留“已知限制”。

## 5. v1.1.0：任务管理补全

### 5.1 计次待办（有限 / 无限）

2026-10-19 按维护者决定调整：本版本只做计次，原周期待办暂缓。

- 任务详情提供可选“计次”设置：普通任务（默认）、有限次数、无限累计。有限次数的目标为正整数；无限累计没有目标上限。
- 卡片显示当前进度和明确的“记录一次（+1）”按钮；普通勾选仍表示结束整个任务，不改变现有操作习惯。
- 有限计次达到目标后自动完成；无限计次持续累计，也可用原勾选手动结束。误点支持撤销；重新打开达到目标的有限任务时，退回目标前一次。
- 计次不生成新任务、不改变截止时间或提醒、不自动占用日程；日程仍引用同一个任务。
- 使用可空 `countProgress: {value, target?}`，缺省表示普通任务；备份格式升级到 4，继续导入 1/2/3 版。拒绝向旧格式静默导出有计次的数据。
- 保存、编辑、撤销、备份、多卷恢复保留计次数据；子项自动完成父项不能提前结束计次目标。
- 三种语言同步，覆盖有限到达目标、无限累计、撤销冲突、重启、旧备份、损坏字段及组件操作。

### 周期待办（暂缓，不属于 v1.1.0）

保留原方向：每天/每周/每月/每年、按截止日期或完成日期计算、结束日期或次数、完成历史及系列管理。待需求明确后排期；开发前明确漏做时是否生成下一次、逾期处理和显示规则。

### 5.2 快速记录（M）

- **分享到方寸（Android）**：`AndroidManifest.xml` 为 `MainActivity` 增加 `ACTION_SEND`（`text/plain`）的 intent-filter；新增原生桥接把分享的文字交给 Flutter，打开现有输入面板并预填。多行文字走现有手动批量添加，逐行预览后确认；`brainDump` 是 AI 模式，不用于系统分享。
- **应用快捷方式（Android）**：长按图标出现“新建任务”“今天”。用静态 `shortcuts.xml`，不加新依赖。
- **Windows**：确认全局快捷键唤出窗口后直接聚焦到新建输入框；托盘菜单加“新建任务”。
- 桌面小组件（Android home widget）工作量大且需要新依赖，已排到 v1.4.0。

完成标准：从浏览器分享一段三行文字，导入预览里出现三条任务；冷启动和应用已在后台两种情况都能工作。

### 5.3 Linux 按时提醒与托盘（M–L）

- `flutter_local_notifications` 在 Linux 上不支持定时投递，因此在应用内实现：应用运行（含最小化到托盘）时，用定时器在到点时发出通知；启动时汇总显示错过的提醒。
- 托盘：`tray_manager` 支持 Linux（依赖 `libayatana-appindicator3`，DEB/RPM 已带上），实现关闭到托盘，和 Windows 的行为保持一致。
- 设置里提供“登录时启动”（写入 `~/.config/autostart/compoise.desktop`），默认关闭。
- 全局快捷键在 Wayland 下没有统一方案，本版本不做，在文档里说明。
- 更新[提醒](reminders.md)和 README 的 Linux 说明。

完成标准：在 GNOME 和 KDE 上手动验证到点通知、错过补发、关闭到托盘；单元测试覆盖调度器（用假时钟）。

## 6. v1.2.0：可选同步

状态：规划中。**6.4 的传输方式和首批网盘需维护者确认后才开工**；确认后新建 `docs/v1.2.0-execution.md` 记录执行情况。

原则：同步默认关闭；不引入方寸自己的账号和服务器，用户连接的是自己的网盘或文件夹；网盘里只有密文；本地双槽提交、启动恢复保持不变，同步失败只影响同步本身。

### 6.1 规模基准（S）

- 同步每次都要生成并加密快照，先量清楚数据量的影响。基准测试：1k / 5k / 20k 条任务时，启动加载、单次修改到提交完成、生成同步快照并加密的耗时和体积，在 CI 中记录。
- 结果用于决定同步快照是否需要分片或增量上传，以及 v1.5.0 的归档是否需要做。
- **存储引擎决策点**：如果 5k 条时单次提交超过 100 ms，再立项迁移到 SQLite（如 drift），保留现有的事务、校验和启动恢复语义；否则继续用当前方案。不提前迁移。

### 6.2 加密模块（M）

- 新增通用加密模块：用 Argon2id（或迭代数足够高的 PBKDF2-SHA256）从同步密码派生密钥，用 AES-256-GCM 加密；文件头记录格式版本和算法参数。需要新增依赖（如 `cryptography`），先评估许可证和各平台实现。
- 同步密码不上传、不进备份；本机只在系统安全存储（Android Keystore、Windows 凭据存储、Linux Secret Service）里保存派生后的密钥。忘记同步密码时，网盘上的数据无法解密，但本机数据不受影响，可以换新密码重新上传。
- 接口按通用设计，v1.5.0 的加密备份直接复用。

完成标准：已知答案测试；密码错误、文件损坏、内容被篡改三种情况能区分并给出不同提示。

### 6.3 同步内核转正（M–L）

- **从实验转为正式**：`lib/experiments/wp18_sync/` 已经有快照、差异、合并和传输边界（`SyncTransport`、`TransportCapabilities`）的原型，以及基于目录的假传输。先补齐测试，再改名移到 `lib/sync/`。
- **每台设备只写自己的文件**：每台设备在同步位置下只写自己目录里的加密快照和头文件，只读取其他设备的文件。这样不同设备不会同时改同一个文件，不依赖网盘支持条件写入，普通网盘和同步文件夹也能安全使用。文件名不含任务内容。
- **冲突**：按字段合并，结果确定且可重复；无法自动合并时保留两份，在界面里让用户选择。删除用墓碑（tombstone）记录，保证第三台设备加入后也不会复活已删除的任务；墓碑在所有已知设备都同步过之后再清理。
- **设备管理**：列出已同步的设备和最后同步时间，可以移除不再使用的设备。
- **范围**：同步任务、任务板、日程和普通设置；API 密钥、网盘登录令牌和只与本机相关的状态（窗口位置等）不同步。

完成标准：两台设备离线各自修改后合并结果确定且可重复；断网、重复投递、半写入文件都不会损坏本地数据（原型的假传输已有这些用例，迁移后继续保留）。

### 6.4 传输方式（方案待维护者确认）

以下是提议，开工前由维护者确认首批范围。

**首批**

1. **WebDAV**：填写地址、账号和应用密码即可。覆盖坚果云、Nextcloud、群晖等；也可以用 OpenList（AList）把百度网盘、夸克、123 云盘等挂成 WebDAV 后使用。坚果云需在“账户信息 → 安全选项 → 第三方应用管理”生成应用密码，并有请求频率限制（免费版 30 分钟 600 次）和单次列目录 750 项的上限，因此要合并请求、失败后退避重试。
2. **OneDrive**：点“连接”后在浏览器打开微软官方登录页（可扫码或输入密码），同意后回到方寸，用户不需要自己申请任何密钥。用 OAuth 2.0 授权码 + PKCE，客户端不保存密钥；权限只申请 `Files.ReadWrite.AppFolder`，只能访问“应用/方寸”文件夹。首批只支持个人 Microsoft 账户。维护者需在 Microsoft Entra 免费注册一次应用。
3. **同步文件夹（桌面端）**：选择一个本地目录，由 Syncthing、坚果云、OneDrive 等任意同步客户端负责同步。Android 只支持真实的本地目录（如 Syncthing 同步的目录）。

**第二批（评估）**

- Dropbox：官方支持开源应用用 PKCE，可只访问应用文件夹；未通过上线审核前最多 500 个用户；国内无法直接访问。
- Google Drive：可用隐藏的应用数据文件夹（`drive.appdata`，非敏感权限）；需要品牌验证；国内无法直接访问。
- 百度网盘：有官方 OAuth 和扫码登录，但换取和刷新令牌需要 SecretKey，开源应用无法保密；个人开发者能否创建应用和上线审核需维护者在开放平台确认。

**不直接支持**：夸克 / UC、迅雷网盘、123 云盘开放平台、MEGA、MediaFire 等没有适合开源客户端的公开授权方式（或需要每个用户自备开发者凭据、付费权益、在应用内输入网盘密码）。需要时可通过 OpenList 等工具转成 WebDAV。

**登录实现**：Android 用系统浏览器授权，通过自定义 scheme 回到应用；Windows / Linux 在本机 `127.0.0.1` 临时监听回调。令牌只存系统安全存储，不同步、不进备份；断开连接时删除。

### 6.5 界面、时机与文档（M）

- 设置 → 同步：选择方式、连接、设置同步密码、立即同步、上次同步时间和错误提示、断开连接。
- 自动同步时机：启动时、修改后延时几秒、回到前台时；失败时在后台重试并写诊断日志，不打断操作。
- 新增同步说明文档，更新[隐私说明](privacy-policy.md)：开启后数据以密文形式上传到用户选择的位置。三种语言同步。

完成标准：每种首批传输方式用真实账号手动验证首次上传、第二台设备加入、双向修改、删除不复活；限频、令牌过期、断网时本地数据不受影响，界面有明确提示。

## 7. v1.3.0：月视图与 AI 指令

### 7.1 月视图（M）

- `PlannerView` 增加 `month`。每天下面用圆点表示有内容：日程和截止日期用不同颜色区分；点某一天进入该天的日视图。
- 周起始日与现有周视图一致；三种语言和窄屏布局同步验证。

### 7.2 AI 指令框（M–L）

- **不做对话界面**：复用现有输入面板的 AI 模式（`brainDump`），在四象限页用一个输入框接收指令，例如“把下周到期的都移到重要紧急”。
- AI 只负责识别意图，输出 JSON 动作列表；由应用里的固定工具执行：批量移动象限、修改截止日期、设置提醒、移到其他任务板、加减标签、标记完成。**AI 不能删除任务**，最多标记完成。
- 执行前列出预览，确认后执行，可一次撤销；指令不明确时用一句话追问，不猜。
- 只发送当前任务板未完成任务的标题、象限和截止日期。

### 7.3 一句话新建与分类理由（S–M）

- 一句话新建任务时，AI 同时给出象限、截止日期和一句分类理由；理由只在预览里显示，不保存到任务。
- AI 返回的 JSON 新增可选 `reason` 字段，旧格式继续兼容。

完成标准：用假 AI 客户端测试动作解析、非法 JSON 和未知动作被拒绝、超出范围的任务 ID 被忽略、撤销恢复原状。

## 8. v1.4.0：桌面入口与排程

### 8.1 Android 桌面小组件（M–L）

- 两种小组件：“今天”和“四象限”。第一版只读：显示任务，点任务打开对应位置，点“+”走快速记录新建。
- 在小组件上直接勾选完成以后再做。
- 需要新依赖（如 `home_widget`），先评估许可证和维护情况；数据变化时刷新小组件。

### 8.2 AI 排进日程（M–L）

- AI 决定排哪些任务、先后顺序和每项时长；具体放到哪个空闲时段由应用代码计算（复用 `scheduleIntervalsOverlap`），避免与已有日程冲突。
- 记住用户的作息（可安排的时间段），作为本机设置。
- 先预览再确认，可一次撤销。

## 9. v1.5.0：数据安全与规模

### 9.1 自动备份（M）

- 设置里开启后，每天第一次启动（或每次数据有变化的当天结束时）把备份写到一个文件夹：默认应用数据目录，可改到用户选择的文件夹（Android 用 SAF 目录授权）。
- 保留最近 N 份（默认 7），超出的自动删除。
- 复用 `backup_export.dart`，默认**不含密钥**。

### 9.2 加密备份（M）

- 导出时可设置密码，复用 v1.2.0 的加密模块。
- 勾选“包含 API 密钥”时**强制**加密，去掉现在的明文选项。
- 导入时识别加密文件并要求输入密码；密码错误和文件损坏给出不同的提示。

### 9.3 已完成任务归档（M，视基准结果）

- 根据 v1.2.0 的规模基准决定是否需要。需要时增加“归档已完成超过 N 天的任务”：归档数据单独存放、不进每次的快照，但仍在“已完成”和搜索里可查，并包含在备份和同步中。

### 9.4 导出到日历（S）

- 把日程和带截止时间的任务导出为 `.ics` 文件，供其他日历导入。只导出，不订阅，不双向同步。

## 12. 明确不做

- 账号体系、自建云服务、自建 AI 中转。
- 默认开启的任何联网功能（检查更新、同步都必须由用户开启）。
- 托管 AI 服务（`experiments/wp29_hosted_ai`）：与 BYOK 定位冲突，近期不转正。
- iOS / macOS：目前没有 Mac 开发机和 Apple 开发者账号（每年 99 美元），等用户规模起来后再评估。
- 网页版：浏览器里无法可靠地按时提醒；数据存在浏览器存储里，容易被清理；没有安全保存 API 密钥的地方；截图识别依赖本地模型；部分 AI 服务不允许浏览器直接跨域调用；另有 21 个文件依赖 `dart:io`。
- AI 对话界面、AI 周报、鼓励语和用户画像。
- 番茄钟、习惯打卡、农历。
- 团队协作、任务分配、评论等多人功能。

## 13. 风险

| 风险 | 应对 |
| --- | --- |
| 备份格式升级导致旧版本读不了新备份 | 版本号递增，旧版本明确拒绝而不是部分导入；导出时提供“兼容旧版本”选项并提示会丢失的字段 |
| 重复任务的日期计算出错，影响提醒 | 规则计算做成纯函数，覆盖月末、闰年、夏令时；上线前用 `-ci` 标签发预览版自测一周 |
| Android 厂商省电策略导致提醒不准 | 继续完善权限引导（#17、#18 已开始）；诊断日志记录排程和实际触发时间，方便定位 |
| 同步引入数据损坏 | 先完成规模基准和加密模块，再接入传输；每台设备只写自己的文件；本地双槽提交保持不变，同步失败只影响同步本身；正式发布前用 `-ci` 标签多设备自测 |
| 网盘接口变化、限频或令牌失效 | 传输层隔离在 `SyncTransport` 后面；限频时退避重试；令牌失效时提示重新连接，本地数据不受影响 |
| AI 指令误改任务 | AI 只能调用固定动作、不能删除；执行前预览，可一次撤销 |
| 一人维护、精力有限 | 每版只带一两个主要功能；`good first issue` 和翻译任务开放给社区 |

## 14. 怎么推进

1. 按本文为每一节建 GitHub issue，挂到对应 Milestone（`v1.0.1`、`v1.1.0`……）。
2. 每个 issue 一个分支、一个 PR；PR 描述里写清楚完成标准对应的测试。
3. 发版前先打 `vX.Y.Z-ci.N` 标签试跑，在真机上过一遍主流程，再打正式标签。
4. 每个版本发布后回到本文，更新“现状”和下一版本的内容。
