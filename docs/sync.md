# 同步

v1.2.0 起可以选择开启同步。本文说明同步的数据格式、合并规则和安全设计，供维护者和想核对实现的用户参考。界面见下文[设置页](#设置页)。

代码在 `lib/sync/`，测试在 `test/sync_*_test.dart`。

## 原则

- **默认关闭。** 不开启时，方寸不会联网同步任何数据。
- **没有方寸账号和服务器。** 数据放在用户自己的网盘里；方寸只读写这个网盘里属于它的一个文件夹。
- **密码可选。** 设置同步密码后，网盘里只有密文；不设置时，文件只做压缩，网盘服务商能看到内容。
- **本机数据优先。** 同步出错只影响同步本身。同步结果写回任务库前逐条校验，再用和导入备份相同的原子提交写入，失败会完整回滚。

## 同步位置

| 位置 | 状态 | 说明 |
| --- | --- | --- |
| OneDrive | 已完成（待真实账户实测） | 用个人 Microsoft 账户登录，使用 OneDrive 的“应用/Compoise”文件夹，方寸看不到网盘里的其他文件 |
| 华为云空间 | v1.2.0 不做 | 原因见 [v1.2.0 执行记录](v1.2.0-execution.md#华为云空间) |
| WebDAV | 已完成（高级选项） | 坚果云、Nextcloud、群晖等；需要填写地址、账号和应用密码 |

## 文件夹里的文件

```text
vault.json            同步库说明：库 ID、历史 ID、加密参数。明文 JSON，不含任务内容
dev-<设备ID>.cps      每台设备一个文件：这台设备合并后的完整同步数据
```

- **每台设备只写自己的文件**，只读别人的文件。不同设备永远不会同时改同一个文件，所以不依赖网盘的条件写入或文件锁。
- 文件名只包含随机生成的设备 ID，不含任务内容或设备名。
- 每个设备文件都包含完整数据，所以新设备加入时，只要有一个设备文件是新的就能拿到全部内容。

### vault.json

```json
{
  "app": "compoise",
  "kind": "vault",
  "format": 1,
  "vaultId": "随机 ID",
  "createdAt": 1735689600000,
  "lineage": ["上一个库 ID"],
  "encryption": {
    "kdf": { "name": "argon2id", "memoryKiB": 19456, "iterations": 2, "parallelism": 1, "salt": "Base64" },
    "check": "Base64（用密钥加密的校验块）"
  }
}
```

不设密码时 `encryption` 为 `null`。修改或取消密码会生成新的 `vaultId`，并把旧 ID 放进 `lineage`，见[修改密码](#修改密码)。

### 设备文件（`.cps`）

```text
"CPS1" | 版本(1 字节) | 模式(1 字节) | 随机数(12 字节，仅模式 1) | 内容
```

- 模式 0：gzip 压缩，不加密。读取时校验 gzip 的 CRC-32 和长度，上传中断留下的半截文件会被识别出来。
- 模式 1：先 gzip，再用 AES-256-GCM 加密；内容末尾是 16 字节认证标签。文件头和文件名一起作为附加认证数据，所以改文件头、改文件名或调换两个设备的文件都会被发现。
- 解压后的内容是 JSON：`app`、`kind: "device"`、`format`、`vaultId`、设备信息（ID、名称、平台、版本）、写入时间和同步状态 `state`。

## 加密

- 密钥由同步密码经 **Argon2id** 派生（OWASP 推荐的最低配置：19 MiB 内存、2 轮、1 线程，16 字节随机盐），再用 **AES-256-GCM** 加密。实现来自 [`cryptography`](https://pub.dev/packages/cryptography) 包（Apache-2.0，纯 Dart）。
- **密码不保存、不上传、不进备份。** 本机只在系统安全存储里保存派生后的密钥，和 API 密钥同样的方式。
- 输入密码时先用 `vault.json` 里的校验块验证，所以“密码错误”和“文件损坏/被改动”是两种不同的提示。
- 一个加密的同步库会拒绝读取明文设备文件，防止有网盘写权限的人塞进未加密的内容。
- 忘记密码时网盘上的数据无法解密，但本机数据不受影响；可以断开后用新密码重新创建同步库。

已知答案测试见 `test/sync_crypto_test.dart`（Argon2id 参考值来自 libargon2，AES-GCM 用 GCM 规范测试用例 16）。

## 合并规则

同步状态由“记录”组成：每个任务板、任务、子项、日程项各是一条记录，普通设置合成一条记录。

- **按字段合并。** 每个字段都带一个时钟值，合并时保留时钟更新的值。两台设备改了同一任务的不同字段（例如一台改标题、一台改备注），两处修改都保留。
- **同一字段两边都改了，保留较晚的修改。** 时间相同时按值的内容决定，保证每台设备得到相同结果。备注不做逐行文本合并。
- **时钟**是混合逻辑时钟：毫秒时间 × 1024 + 计数。设备合并过别人的数据后，自己之后的修改一定排在后面，即使两台设备的系统时间不一致。修改在发生后几秒内就记下时间，离线一天再联网，也不会把早上的修改当成晚上的。
- **删除**记为墓碑（tombstone）。墓碑永久保留（每条只有 ID 和时钟），所以之后加入的设备、或从旧备份恢复的数据都不会把已删除的任务带回来。
- **删除和修改同时发生时，修改胜出**：一台设备删除任务的同时，另一台离线设备改了它，合并后任务保留（含修改）。随任务一起删除的子项也随之恢复；之前单独删除的子项不恢复。
- **已删除内容保留 30 天**，以便上面这种情况能恢复完整的任务；30 天后只留墓碑，内容从同步文件里清除。
- **日程项整条合并**，不拆字段，避免拼出一条哪台设备都没写过的日程。
- **顺序**：任务、子项、任务板的排列位置也是一个字段，合并后按位置排序，相同位置按 ID 排。
- **修复**：合并结果里如果任务所在的任务板已被删除，任务移到第一个任务板；所有任务板都被删除时，恢复最近修改过的那个；任务已删除的时间块一并删除。
- **看不懂的记录保留不动**：新版本写入的、当前版本读不了的记录不会被删除，升级后仍能使用。

合并满足交换律、结合律和幂等性：设备之间以任何顺序、任何次数交换文件，最终结果都相同。测试见 `test/sync_state_test.dart`（随机化验证）和 `test/sync_engine_test.dart`（三台设备随机离线修改后收敛）。

## 同步哪些内容

| 同步 | 不同步 |
| --- | --- |
| 任务板、任务、子项、日程 | API 密钥、网盘登录令牌 |
| 语言、主题、主题色、默认输入方式、AI 自动分组/拆分、自动完成父任务、提示开关、隐藏已完成、显示完成率、漫画描边、拟态风格、紧急阈值 | 视图模式、字号、字体、减少动态效果、关闭到托盘、全局快捷键、窗口位置 |
| | 提醒的投递记录（每台设备按同步来的任务自己安排提醒） |

启动恢复还没处理完时（有待恢复的文字），同步暂停，避免把恢复了一半的内容传到其他设备。

## 一轮同步

1. 读取当前任务库和它的修订号。
2. 列出文件夹，读取 `vault.json`，检查库 ID 和密码。
3. 下载有变化的其他设备文件（按网盘返回的版本号判断）。
4. 在后台线程里解密、合并、生成新的任务库和本机下一次要上传的文件。
5. 结果和当前任务库不同时，写回任务库。写回前如果用户又改了内容，这次结果作废，从第 1 步重来（最多 3 次），不会覆盖刚输入的内容。
6. 写回成功后保存同步状态，再上传本机文件（内容没变就不上传）。

任何一步失败，任务库都保持原样，下次同步从头再来。保存同步状态前会先记一份“待确认”状态，万一在写回任务库和保存状态之间崩溃，下次启动能识别出任务库已经是新结果。

## 何时同步

- 修改保存后约 4 秒，先在本机给修改盖上时间（不联网）。这样离线时的修改按真实修改时间参与合并，不会因为很久以后才联网而盖过别处更新的修改。
- 第一次修改后约 20 秒联网同步一轮；持续编辑时最多每 20 秒一轮。
- 启动后 3 秒、回到前台（距上次超过 1 分钟）、前台时每 10 分钟各同步一轮。
- 切到后台时，如果还有没上传的修改，立即同步一轮。
- 断网、服务器错误、限频时依次等待 30 秒、1、2、4、8 分钟，之后每 15 分钟重试；服务器要求等待更久时按服务器的时间。
- 账号或密码被拒、同步库被删除或换了密码、需要输入同步密码时，停止自动同步，等用户处理；“立即同步”不受限制。
- 任务库还没保存成功，或启动恢复还没处理完时，不盖时间也不同步，以免把缺失的内容当成删除。

刚从同步下载并写入的内容不会触发下一轮同步。

## 设置页

设置 → 同步：

- 没有开启时，显示同步的说明和可选的同步位置：OneDrive（推荐）和 WebDAV（高级）。
- 连接 OneDrive：填写本机名称，点“登录 Microsoft 账号”，在浏览器里登录并同意授权；回到方寸后自动检查应用文件夹里有没有同步库，后面的步骤和 WebDAV 相同。浏览器打不开时，等待登录的对话框里可以复制登录链接。
- 连接 WebDAV：填写地址、账号、密码和本机名称，点“连接”后先检查能否登录、文件夹里有没有同步库。这一步不保存任何设置。
  - 还没有同步库：可以设置同步密码（至少 8 位，输入两次），再点“开始同步”新建。
  - 已有同步库：显示已有几台设备；同步库加密时要输入同步密码才能加入。
- 开启后显示同步状态和上次同步时间，可以“立即同步”、查看设备、改本机名称、移除其他设备、设置/修改/取消同步密码。
- 需要处理时，状态下面直接给出操作：服务器拒绝登录时重新输入服务器密码（OneDrive 是“重新登录”，必须用原来的账号）；其他设备改了同步密码时输入新密码；其他设备取消了密码时确认是否继续。
- 断开同步：本机停止同步，删除本机的同步设置和保存的密码，任务不受影响。可以勾选同时删除本机在网盘上的文件。

## OneDrive

- 只支持个人 Microsoft 账户（outlook.com、hotmail.com、live.com 等）。应用注册只允许个人账户，工作或学校账户不能登录。
- 登录用 OAuth 2.0 授权码 + PKCE（S256），没有客户端密钥；客户端 ID 是公开的，写在 `lib/sync/onedrive_auth.dart`。请求的范围是 `Files.ReadWrite.AppFolder offline_access openid profile`：只能读写 OneDrive 的应用文件夹；`offline_access` 用来拿刷新令牌；`openid profile` 只用来显示登录的账号。
- 桌面版在 127.0.0.1（以及 ::1）的随机端口上临时开一个本机服务，回调地址是 `http://localhost:端口`，收到回调后立即关闭，浏览器里显示“已登录，可以关闭这个页面”。Android 版打开系统浏览器，登录后通过 `com.compoise.app://oauth` 回到方寸。用随机的 `state` 对应每次登录，不匹配的回调被忽略；10 分钟内没完成算超时。
- 刷新令牌、访问令牌和过期时间存在系统安全存储（`compoise-sync-provider-secret`），不写文件。访问令牌过期前 5 分钟内，或 Graph 返回 401 时刷新一次；微软返回新的刷新令牌时立即保存。刷新令牌失效（例如在微软账户里撤销了授权）时提示重新登录。重新登录时比较 ID 令牌里的账号 ID，换成别的账号会被拒绝（它的应用文件夹是另一份数据），要换账号请先断开。
- 文件放在 Graph 的 `me/drive/special/approot`（OneDrive 里显示为“应用/Compoise”），按文件名读写。列目录时跟随分页链接，但只接受 `graph.microsoft.com` 的链接；下载走 Graph 重定向到的预授权链接，不带访问令牌；4 MB 以内直接上传，更大的文件用上传会话分片（每片 3.2 MB，同样不带访问令牌）；新建 `vault.json` 用 `conflictBehavior=fail`，已存在时报冲突。版本号用 eTag。
- 被限频（429、509，或带 Retry-After 的 503）时按服务器要求等待。
- 日志只记录请求类型、HTTP 状态和错误代码（例如 `token: HTTP 400 invalid_grant AADSTS70008`），不记录账号、链接和令牌。

## WebDAV

在填写的地址下使用 `Compoise/` 文件夹，第一次上传时自动创建。只用 PROPFIND（深度 1）、GET、PUT、MKCOL、DELETE 五种请求，不依赖锁、移动和复制。

- 地址必须是 http 或 https，不能带用户名、查询参数或片段。公网地址用 http 时设置页会提示风险；局域网地址（如 192.168.x.x、`.local`）不提示。
- 版本号优先用 ETag，服务器不给 ETag 时用修改时间加大小。
- 创建 `vault.json` 时先列目录再带 `If-None-Match: *` 上传，两台设备同时建库时只有一台成功。
- 坚果云要用第三方应用密码，不能用登录密码；在坚果云网页版或客户端的安全设置里生成（有的帐号在网页版找不到入口，可以用客户端）。坚果云对 WebDAV 请求有频率限制，方寸每轮只发几个请求，空闲时 10 分钟一轮；被限频（429 或带 Retry-After 的 503）时按服务器要求等待。
- 可以用 `COMPOISE_WEBDAV_URL`、`COMPOISE_WEBDAV_USER`、`COMPOISE_WEBDAV_PASSWORD` 运行 `test/live/webdav_live_test.dart`，对真实服务器做一次读写和两台设备同步的检查。它在新建的 `Compoise-test-…` 文件夹里进行，结束后删除写入的文件。

## 加入同步库

- **新建**：文件夹里还没有同步库时创建，本机数据作为初始内容。
- **合并**：保留本机数据并加入同步库；同一条记录两边都有时以同步库为准，已在同步库里删除的不会被本机旧数据带回来。
- **用同步库替换本机**：本机数据被同步库内容替换。本机只有初始的空任务板时自动选这种方式，避免多出一个空任务板。同步库里还没有任何数据时不会清空本机。

## 修改密码

设置、修改或取消密码时，先完成一轮同步，再生成新的 `vaultId`（旧 ID 记入 `lineage`），用新密钥重新上传本机文件，并删除其他设备的旧文件。

其他设备下次同步时发现库 ID 变了：

- 新库有密码：提示输入新密码，验证后继续，本机的离线修改和删除都保留。
- 新库取消了密码：提示确认后才继续，因为之后上传的是明文。
- 新库的 `lineage` 里没有本机所在的库（文件夹被换成了另一个同步库）：停止同步，由用户决定重新加入或断开。

## 设备管理

可以列出设备（名称、平台、最后上传时间），移除不再使用的设备（删除它的文件）。已经合并过的修改不受影响；如果那台设备还在用，它下次同步会重新上传自己的文件。

## 本机文件

保存在应用支持目录的 `sync/` 下，和任务库分开：

| 文件 | 内容 |
| --- | --- |
| `sync-meta.json` | 设备 ID、所在同步库、是否加密、其他设备文件的版本和信息 |
| `sync-state.json` | 合并后的同步状态 |
| `sync-pending.json` | 正在写回任务库的状态，仅在一轮同步中短暂存在 |
| `sync-provider.json` | 用哪种同步位置、WebDAV 地址和用户名或 OneDrive 账号名和账号 ID、本机在设备列表里的名字（不含密码和令牌） |

密钥只放系统安全存储（与 AI 密钥相同的机制）：`compoise-sync-vault-key` 是由同步密码推导出的密钥（不保存密码本身），`compoise-sync-provider-secret` 是 WebDAV 密码或 OneDrive 的登录令牌。Linux 上没有可用的钥匙串时无法保存这两项，同步会提示重新登录。

每次写入都先写临时文件再改名。这些文件丢失或损坏不会丢任务：下一轮把本机任务库当作基线重新合并，同步库里已有的内容和删除优先。

## 已知限制

- 同一字段两边同时修改时只保留较晚的一份，没有“保留两份让用户选择”的界面。
- 墓碑不清理。删除很多条目后，同步文件会多出每条约几十字节。
- 每台设备都上传完整状态；任务很多时上传和合并需要几秒，在后台线程进行，不阻塞界面。
