- **WP17-I4**：确认权重来源和分发依据，建立可复现的模型/原生依赖准备与打包；在带 OCR 依赖的 Linux Flutter bundle 上验证加载。未通过的模型、平台和真实截图质量门禁保持未验收。
- **WP28-U1**：处理 Windows 历史数据目录的升级保留，验证新旧目录并存、损坏与失败重试；不改品牌身份，不动真实用户库。正式签名与 Release 仍另行验收。

并行边界：D1 负责导航/设备时区与对应文案，I4 负责 OCR 依赖和平台构建配置，U1 负责 Windows 启动升级适配。共享构建与启动文件应由单一包负责；各包只更新自己的验收记录，公共文档由集成端统一维护。WP17 正式发布仍需模型权重再分发依据、Android arm64 真机识别和真实截图质量证据；独立组件测试不能替代这些门禁。

WP17 的旧[系统笔记接口研究](evidence/wp17r/README.md)保留为历史证据，不再是新范围的前置条件。WP28 的 Windows 数据目录升级兼容仍是发行前的独立门禁；WP19 可重新拆解，WP18、WP29 暂缓到核心任务流稳定后再评估。

轻拟态实验可单独领取：先在共同基线上试工具栏、输入区和按钮，再对比 Android / Windows 的明暗主题、字体和交互性能，最后决定是否合入主线。它不必等 WP14–WP19 或 WP29 完成。
