## 后续接线与门禁

WP17-I5 与 WP28-U2 已集成；WP15-D2 在独立工作树实施，本轮未集成它的进行中改动。

- **WP15-D2**：在 Android 与 Linux 验收日程入口、设备时区、运行中变更、DST 与备份重开；修正实测缺陷，补可复用的隔离设备验收工具。Windows 实机界面与读屏缺项如实记录。
- **WP17-I5 已实现**：[官方模型转换记录](WP17_I5_NOTES.md)固定输入、工具链与输出，经独立重复转换及 Windows/Linux 原生对照；后续仍需官方模型的应用 bundle、Android 完整导入及真实截图质量。
- **WP28-U2 已实现**：[升级与退出记录](WP28_U2_NOTES.md)区分说明已读与密钥重配状态，修复窗口/引擎与 COM 销毁顺序；隔离 Debug/Release 均有完整矩阵证据，正式签名、tag 与渠道发布仍单独验收。

运行边界：D2 使用 Android 日程验收设备；后续 OCR 设备包在它释放设备后验收，不能在同一设备上互相覆盖安装或时区。I4 的 arm64 真机原生识别和 Linux bundle 库证据使用历史验证权重，I5 的官方转换对照在 Windows/Linux 原生库完成；都不能替代官方模型 Flutter SAF → OCR → 校对 → 写库的完整设备流程。

WP17 的旧[系统笔记接口研究](evidence/wp17r/README.md)保留为历史证据，不再是新范围的前置条件。WP28 的 Windows 数据目录升级兼容仍是发行前的独立门禁；WP19 可重新拆解，WP18、WP29 暂缓到核心任务流稳定后再评估。

轻拟态实验可单独领取：先在共同基线上试工具栏、输入区和按钮，再对比 Android / Windows 的明暗主题、字体和交互性能，最后决定是否合入主线。它不必等 WP14–WP19 或 WP29 完成。
