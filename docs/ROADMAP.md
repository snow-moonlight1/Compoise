## 后续接线与门禁

WP15-D1、WP17-I4 与 WP28-U1 已集成。下一批可并行推进：

- **WP15-D2**：在 Android 与 Linux 验收日程入口、设备时区、运行中变更、DST 与备份重开；修正实测缺陷，补可复用的隔离设备验收工具。Windows 实机界面与读屏缺项如实记录。
- **WP17-I5**：用已固定的官方输入跑通 PIR → ONNX → ncnn 转换，锁定实际可用工具链与产物哈希，补许可与部署证据；先做 Windows/Linux 原生对照，不占用本批 Android 设备。
- **WP28-U2**：收口 Windows 隔离升级、退出、重开与单实例原生验收；明确加密凭据重配提示的确认生命周期。正式签名、tag 与渠道发布仍单独验收。

并行边界：D2 负责日程、时区及 Android/Linux 界面验收；I5 负责 OCR 转换与依赖脚本，不修改平台 runner 或启动；U2 负责 Windows 启动升级与原生进程验收。各包只更新自己的记录，公共文档由集成端维护。I4 已有 arm64 真机原生识别和 Linux bundle 库加载证据，仍不能替代 Flutter SAF → OCR → 校对 → 写库的完整设备流程、官方模型与真实截图质量验收。

WP17 的旧[系统笔记接口研究](evidence/wp17r/README.md)保留为历史证据，不再是新范围的前置条件。WP28 的 Windows 数据目录升级兼容仍是发行前的独立门禁；WP19 可重新拆解，WP18、WP29 暂缓到核心任务流稳定后再评估。

轻拟态实验可单独领取：先在共同基线上试工具栏、输入区和按钮，再对比 Android / Windows 的明暗主题、字体和交互性能，最后决定是否合入主线。它不必等 WP14–WP19 或 WP29 完成。
