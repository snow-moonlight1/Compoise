## 下一批可并行

WP15-A1、WP16 与 WP17-R2 已集成。下一轮的三个子包从本次集成后的主线分支各开独立工作树，避免共享文件改动：

- **WP15-A2**：接入 A1 日程模型到 Store 与 SaveProtocol 双槽快照，维护任务/板删除、编组、撤销时的引用；只改本地事务和必要模型/测试，不改备份 v3、Planner UI 或 WP17 文件。验收旧库缺键、坏键恢复、保存失败回滚和重开往返。
- **WP17-I1**：把 R2 的 ncnn CPU 识别核心整理为可调用的跨平台运行时，明确模型来源、许可与哈希，在 Windows、Linux 和 Android API 23 验证可构建/加载；真机 arm64 若不可用须如实记门禁。只改原生桥接、构建与隔离的 OCR API/测试，不改任务库、导入 UI 或 WP15 文件。
- **WP17-I2**：以 `wp17r2-draft/1` 为输入，做多图顺序、逐图错误、可编辑草稿、歧义标记与整批确认预览；OCR 和提交均用可注入回调/假实现。只改独立 Dart 草稿/预览组件与测试，不接 Store、不改原生桥接或 WP15 文件。用户取消或有未确认项时不能触发提交回调。

WP17-I1/I2 合并后再做图片选择器与 OCR/Store 接线的 **WP17-I3**；WP15-B 备份 v3 待 A2 稳定后启动。I1/I2 的同名接口以 [R2 草稿契约](WP17_OCR_EVALUATION.md#识别结果--可编辑任务草稿数据契约)为基线，新增代码分别放在 `lib/ocr/` 与 `lib/import_preview/`，不要并发改对方目录。

WP17 的旧[系统笔记接口研究](evidence/wp17r/README.md)保留为历史证据，不再是新范围的前置条件。WP28 的 Windows 数据目录升级兼容仍是发行前的独立门禁；WP19 可重新拆解，WP18、WP29 暂缓到核心任务流稳定后再评估。

轻拟态实验可单独领取：先在共同基线上试工具栏、输入区和按钮，再对比 Android / Windows 的明暗主题、字体和交互性能，最后决定是否合入主线。它不必等 WP14–WP19 或 WP29 完成。
