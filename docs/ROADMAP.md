## 后续接线与门禁

WP15-B1/C1 与 WP17-I3a 已集成。下一步尚需：

- **WP15-B2**：在设置页展示日程导入新增/冲突/删除数量；旧版有损导出须先显示丢失数量并由用户主动确认，调用 B1 的数据层门禁。
- **WP15-C2/D**：补日程新建、编辑、拖动及首页入口；完成三端设备时区、夏令时与辅助技术验收。C1 视图要求提供明确的 IANA 显示时区，不能凭偏移猜测。
- **WP17-I3b**：把 I3a 草稿挂载到应用导航，校对确认后一次写入 Store。Android 当前默认选图入口因插件缓存复制与 URI 日志问题被 I3a 关闭，须先提供符合边界的入口。

这些接线工作会涉及共享的导航和文案文件，实施前需明确文件归属。WP17 正式发布仍需模型权重再分发依据、Android arm64 真机识别和带 OCR 依赖的 Linux Flutter bundle 验证；独立组件测试不能替代这些门禁。

WP17 的旧[系统笔记接口研究](evidence/wp17r/README.md)保留为历史证据，不再是新范围的前置条件。WP28 的 Windows 数据目录升级兼容仍是发行前的独立门禁；WP19 可重新拆解，WP18、WP29 暂缓到核心任务流稳定后再评估。

轻拟态实验可单独领取：先在共同基线上试工具栏、输入区和按钮，再对比 Android / Windows 的明暗主题、字体和交互性能，最后决定是否合入主线。它不必等 WP14–WP19 或 WP29 完成。
