## 下一批可并行

WP15-A2、WP17-I1/I2 已集成。下一轮可从同一主线提交分别开工作树，并行推进三个**互不接线**的子包：

- **WP15-B1**：完成备份 v3 数据层：导出、预检、覆盖/合并、分卷与恢复模拟。可改备份/迁移、Store 导入导出和数据契约文档；不改日程 UI、OCR 或导航。旧版有损导出必须由调用方显式确认，留下可供 UI 展示的丢失数量。
- **WP15-C1**：以只读 Store 数据或注入快照实现 Planner/Schedule 日/周视图、板筛选、跨日裁剪与重叠可访问布局。只改新增视图/布局和对应文案、测试；不改 Store、备份、首页导航。表单、拖动与主入口留给 C2/D。
- **WP17-I3a**：实现多图选择与 OCR 结果到 `wp17r2-draft/1` 的适配；逐图失败、顺序、大小限制、歧义标记可测试。只改新增截图捕获/适配模块和测试；通过现有 I1/I2 接口，不改 Store、备份、原生 C++ 或全局导航。模型缺失时明确失败，不声称正式可用。

这三包集成后，再做 WP15-B2 用户可见的有损提示、WP15-C2 编辑交互、WP17-I3b 校对提交到 Store 与导航接线。WP17 正式发布仍需模型权重再分发依据、Android arm64 真机识别和 Linux Flutter bundle 验证；这些门禁不能用独立组件测试代替。

WP17 的旧[系统笔记接口研究](evidence/wp17r/README.md)保留为历史证据，不再是新范围的前置条件。WP28 的 Windows 数据目录升级兼容仍是发行前的独立门禁；WP19 可重新拆解，WP18、WP29 暂缓到核心任务流稳定后再评估。

轻拟态实验可单独领取：先在共同基线上试工具栏、输入区和按钮，再对比 Android / Windows 的明暗主题、字体和交互性能，最后决定是否合入主线。它不必等 WP14–WP19 或 WP29 完成。
