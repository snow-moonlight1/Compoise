# 设计规范

这些约定来自多轮真机试用后的反馈。新增或修改界面时，请按这里的规则检查。

## 基本原则

**少层、少字、少滑动、少提示。**

- 能一步完成的操作不要拆成两步，能直接生效的操作不要再弹确认表单。
- 浮层尽量不要叠加：新建和编辑用同一个对话框，详情用轻量的工具条，不再弹二级面板。
- 不要把内部概念暴露给用户，例如 UTC 偏移、时区名、状态码、格式版本号、“记录”“端点”之类的术语。只在确实需要时才显示（比如日程的时区和当前时区不同）。

## 文案

- 面向普通用户，用日常用语。按钮写动作（“测试连接”“导出 JSON”），不写实现。
- 用户已经在某个页面上，就不要再说“请到 XX 页面”。直接说要填什么、改什么。
- 不写防御性的说明（“这不代表……”“可能……也可能……”）。说清楚当前结果就够了。
- 失败时用一句话说清原因和下一步，例如“API 密钥不对，请检查后重新粘贴。”“网络连不上，请检查网络或 API 地址。”
- 文案集中在 `lib/l10n.dart`，English、简体中文、日本語三份必须同步。中文用全角标点。

## 提示

- **成功不提示**：保存、移动、拖放、编辑成功都不弹提示，也不显示撤销条。少数没有直接反馈的操作（如发送测试通知）可以用一句很短的话确认。
- **失败一定提示**：用 SnackBar，同一时间只显示一条（新的替换旧的），约 4 秒后自动消失，带关闭按钮。
- **对话框里的错误**显示为对话框内的行内文字，不另弹 SnackBar。
- **删除**前先弹一个居中的确认框（取消 / 删除）。

## 手机与桌面

- 手机和桌面的交互分开设计。改一端时不能改变另一端的行为，也不能改变默认主题。
- 是不是桌面，由平台决定（`lib/ui/platform_ui_policy.dart`），不按窗口宽度判断。
- 桌面端支持：
  - 鼠标悬停、右键菜单、双击；
  - 直接用鼠标拖放，不需要长按；
  - 键盘快捷键；
  - 可调整宽度的侧边任务池，宽度会记住。
- 只有手机才有的入口（比如通知权限按钮）在桌面上隐藏。
- 宽窗口下内容区要限制最大宽度并居中，避免整屏拉伸。

## 触控与布局

- 可点区域至少 48dp，工具栏按钮至少 40dp。
- 页面水平边距保持一致（日程页统一 12dp）。
- 空状态用一行淡色文字说明，不要留一整块空白，也不要堆说明文字。

## 主题与文字裁切

应用有三种外观：默认、漫画描边（`ComicOutline`）和拟态（`NeumorphicSkin`）。后两种在设置 → 外观里开启，默认关闭，而且两者互斥。

- 每个界面改动都要在三种风格下检查，**特别是拟态**。拟态的输入框、按钮和卡片带内外阴影和额外内边距，文字最容易被裁切或挤到边上。
- 拟态下带浮动标签的输入框，输入区比整个输入框低 16dp。这类输入框请用 `lib/theme.dart` 里的 `neuLabelledDecoration` / `neuLabelledAlign`；下拉框用 `neuDropdownDecoration` / `neuDropdownPadding`，让文字在凹槽里垂直居中。
- 检查以下组合：小屏（360dp）、系统字体放大 1.3 倍、中英日三种语言。英文和日文通常最长。
- `test/support/text_clip_probe.dart` 能找出被裁切的文字，可以在组件测试里使用。

## 动画

- 常用曲线是 easeOutCubic，时长 180–280ms。
- 跟手的拖动不加曲线。
- 系统开启“减少动画”时，所有过渡改为立即完成（见 `lib/ui/motion_policy.dart`）。
