# WP15-B1：备份 v3 数据层验收

日期：2026-09-30（Asia/Shanghai）。独立工作树从 `origin/main` 的 `d65780c5e4037ba98a5a2cf9e1bc5418f4bad3f0` 建立，分支 `codex/wp15-b1-backup-v3`；依据 [WP15 契约第 5 节](WP15_CONTRACT.md) 和 [A2 记录](WP15_A2_NOTES.md)。本包只改备份模型、迁移/预检、Store 导入导出、相应测试及格式/兼容文档；无推送。

## 完成行为

- `ExportData` / `Store.exportJson` 默认 v3，日程通过独立 `scheduleItems` 数组往返；两类事件关联和时间块保持绝对时刻与 IANA 时区，任务的计划日、截止、提醒、标签、笔记和配置保留既有含义。
- 缺省版本/v1/v2 继续导入；旧文件碰巧带日程字段时明确提示并忽略。v3 必需数组，未知未来版本仍拒绝。日程复用 A1/A2 的时间、kind、身份和引用校验；未知字段提示，坏时区统一成为格式拒绝。
- 含日程的字符串旧版导出抛 `ScheduleExportLossException(lostScheduleItems)`。调用方主动选择并确认损失后，用 `exportJsonResult` / `exportJsonResultWithCredential` 的 `allowScheduleLoss: true` 获得 JSON 和丢失数量；v1 另有原有字段损失。模型的 `exportResult` 提供相同结果。v3 失败不退回旧版。
- `ImportPlan` 返回日程新增/跳过/冲突/覆盖删除数量，日程也进入总冲突与跳过计数。覆盖替换日程，旧版覆盖清空；合并保留当前集合，相同 ID 同内容跳过，不同内容阻止提交。目标板合并映射独立事件板 ID，关联任务 ID 不变；父任务冲突、无效板或缺失不产生孤儿。
- Store 在预览后及异步写入前重算引用与冲突。日程和任务/板参加同批保存与失败回滚；提交期间接受的后续日程编辑及其依赖保留。回滚恢复内容也推进日程修订号，临时导入记录上的过期编辑/删除会失败。独立只读审查发现这条修订号边界后，已修复并加自动化回归。
- 分卷计入板、任务、日程、重复依赖和配置外壳的转义 JSON 字节。每条日程只出现一次，与其任务/板首次引入同卷；任务文本续卷不重复日程，v3 续卷也有数组。恢复模拟比较全部板、任务、日程和首卷配置（包含主动选择的测试凭据）。损坏、不能装入单卷的不可拆依赖组、或不完整恢复返回失败和空文件集合。

## 容量实测与决定

环境：Windows 主机，固定 Flutter 3.32.8 / Dart 3.8.1；SDK `D:/Dev_SDKs/Flutter_3.32.8`。使用合成数据；时间为本机 Dart 测试 VM 观测，不承诺设备耗时或掉电持久性。

复现：`flutter test --no-pub test/review/wp15_size_measurement.dart --reporter expanded`。该显式测量脚本不使用 `_test.dart` 后缀，不进入普通全量发现；输出字节数、编码/解码或导出加恢复模拟耗时、卷数和每卷实际字节。

| 样本 | 完整 JSON UTF-8 字节 | 卷数 | 最大卷字节 | 构建及恢复模拟耗时 |
|---|---:|---:|---:|---:|
| 500 板、10,000 任务、50,000 子项、10,000 时间块，无大文本 | 5,038,993 | 1 | 5,038,993 | 1,723 ms |
| 同样满数量库，另加 4 MiB 任务笔记 | 9,233,316 | 4 | 4,195,520 | 2,040 ms |
| 10,000 独立事件，10 板，每个标题 4,096 转义字节（双引号转义） | 42,269,944 | 10 | 4,227,116 | 4,992 ms |

第一组编码 83 ms、解码 152 ms；最大标题组编码 429 ms。带 4 MiB 笔记组的四卷实际字节为 `[4195520, 9626, 4191474, 836967]`；其他阶段未单独计时。

据此保留单文件 **8 MiB** 硬上限、深度 **12**，普通文件/合并结果日程数量上限定为 **10,000**，单个事件标题硬上限定为 **4,096 转义 UTF-8 内容字节**（不含两端引号）。**4 MiB** 改为分卷全内容目标预算，不再用 v2 的任务文本/结构估算遗漏日程。实测带 4 MiB 文本的满数量 v3 库已经越过单文件上限，所以必须分卷。最大标题的 10,000 事件需要 10 卷，旧 `maxParts=8` 保留为历史阈值，不作为交付卷数门禁。

正常数量上限约束普通文件和合并后的库；显式 `recovery: true` 延续已有归档规则，只允许数量超限，不绕过字节、标题、深度及数据合法性。单条标题 4,096/4,097 边界覆盖 ASCII、中文和转义字符；10,000/10,001 条覆盖普通输入、合并结果和恢复归档。一个板的全部独立事件，或一个任务及其关联日程必须在首次引入时同卷；2,200 条最大标题事件集中于同一板/任务的样本超过 8 MiB，导出明确失败而非漏记录或输出半套。

## 剩余门禁

本包完成备份 v3 数据层。设置页尚需呈现日程新增/冲突/删除数量、旧文件未知字段和有损导出说明；调用方确认控件及发行迁移提示属于后续 UI/集成验收，数据层已提供计数和默认拒绝门禁。不得在没有展示损失并取得主动选择时设置 `allowScheduleLoss: true`。

Android、Windows、Linux 的真机文件选择、跨平台大库恢复、持久化失败和回退旧可执行文件验收未做；本轮是 Windows Dart VM 自动化。设备时区映射、DST 展示、日程 UI 与发行导航仍属 WP15-C/D。旧可执行文件重写本地槽可能丢日程，发行说明仍需要求先保存完整 v3 备份。

未修改日程 UI、OCR、导航、`lib/l10n.dart` 或 `docs/ROADMAP.md`。A2 记录中的共享 `makeStore` 未 flush 污染通道仍是独立测试卫生议题，本包没有改共享夹具；新增 Store 用例均在重置 mock 前完成提交/销毁。未进行 rebase、合并或推送。
