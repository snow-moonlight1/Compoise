# 今天待办完成庆祝（WP16）

状态：已实现。基线 `96ca181320b303f342adafd5964a0c711cfe0fe7`，分支 `codex/wp16-today-celebration`。
范围只有今天页在「把当前范围内原本非空的未完成列表做完」时的反馈。不改计划日、截止日期、象限，也不引入 WP15 的日程记录。

## 什么时候出现

今天页先记住当前范围里的未完成任务。之后只有这些任务**因为被标成完成而全部离开列表**时才庆祝。

当前范围和 [todayGroups](../lib/storage.dart) 用的是同一套：当前看板，或筛选里的所有看板。判定在 [today_celebration.dart](../lib/today_celebration.dart)。要同时满足：

- 看板或「所有看板」筛选没有变；
- 变化前至少有一行未完成，变化后一行不剩；
- 离开的每一行现在都是已完成。取消计划、把截止日期改出今天、删除，都让任务离开，但完成标志不是 true，所以不算。

会走到这条判定的操作：今天行上的勾选；在今天页详情里保存，使父任务变为完成。后者包括打开「父任务自动完成」后，把最后一条子项勾上并保存。

## 什么时候不出现

下面这些都不会庆祝，也**不会占用**当天这一次：

- 打开页面时列表已经是空的，包括任务在进入今天页之前就已经完成；
- 在「当前看板」和「所有看板」之间切换筛选；
- 切换活动看板；
- 取消计划，或把只因截止日期留在今天的任务改到以后；
- 删掉最后一行；
- 完成一个本来就不在今天列表里的任务；
- 只完成一部分，当前范围里还留着未完成任务；
- 跨日刷新。回到前台时 Store 会做截止日期提升并 `notifyListeners`，整点提升走 `promoteDeadlinesNow`。它们只重新分组，不把未完成任务标完成。

范围变了，或者列表里又出现未完成任务时，已经打开的卡片会收起来，避免句子还指着刚才那个范围。收起不另外占用新的一天。

## 当天只一次，并且要能关掉

闩锁挂在 `Store.todayCelebration` 上，只活在这次进程的内存里。它不是设置，不写入快照、备份或导入预检，所以 [DATA_COMPATIBILITY.md](DATA_COMPATIBILITY.md)、[BACKUP_FORMAT.md](BACKUP_FORMAT.md)、`AppSettings` 和导入白名单都没有新字段。

同一个本地日历日，这次进程里只庆祝一次。关掉今天页再进来，仍然算同一天。进程结束后闩锁消失：同一天若再把一个非空列表做完，会再庆祝一次。这是有意不把临时状态放进保存快照。

卡片不会自己消失。右下角是现有的「关闭 / Close / 閉じる」。关掉只收起卡片；这一天已经用掉。

产品用设备时钟。测试可以换掉闩锁的时钟来跨日；今天列表归哪一天仍由 `todayGroups` 里的 `DateTime.now` 决定，本包没有改那条规则。

## 减少动画

沿用 [MotionPolicy](../lib/ui/motion_policy.dart)：应用里的「减少动画」或系统的 `disableAnimations`，有一个开着就不再淡入。卡片第一帧就是最终样子，关闭按钮当时就能点。两个都关着时，按 `MotionPolicy.celebration`（280ms，easeOut）淡入一次，停在不透明，然后留着直到关闭。

## 未验证

- 没有在真机或真实窗口上看过。Android「移除动画」、Windows「在窗口中显示动画」、Linux 上对应的系统设置都没有拨过；测试只注入了 `MediaQuery.disableAnimations` 和应用内的 `reduceMotion`。`MotionPolicy` 原本就说明，widget 测试里的平台信号不是设备设置的证据。
- 没有用屏幕阅读器确认 `liveRegion` 是否被朗读。
- 没有在 200% 字号、明暗主题、软键盘下看今天页。390×844 只说明这条 widget 测试里关闭按钮点得到、绑定没有报溢出。
- 没有杀进程再打开，验证「重启后同一天会再庆祝一次」。这是内存闩锁的设计，不是设备上跑过的结果。
- 没有跑 `integration_test`，没有打包，没有跑 CI。
- 跨日用例换的是庆祝闩锁的时钟，不是把今天列表的 `DateTime.now` 拨到午夜。真实过午夜时未完成任务会留在「计划已过期」或「到期但未计划」，这条分组规则没有改，也没有在设备上守到零点看过。
