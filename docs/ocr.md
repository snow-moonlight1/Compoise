# 截图识别导入

用户一次选择多张待办清单的截图，应用在本机识别文字并整理成任务草稿，用户校对后一次导入。识别完全离线进行，不会上传图片，也不会读取其他应用的数据。

## 流程

1. **选择截图**：从首页“更多”进入。一次最多选 10 张静态 PNG 或 JPG 截图。单张不超过 16 MiB、4096×8192 像素、1200 万像素，整批不超过 48 MiB。Android 通过系统文件选择器（SAF）读取；Windows 和 Linux 使用系统文件对话框，Linux 上需要 zenity 或 kdialog。
2. **准备模型**：第一次使用时下载识别模型，见下文“模型”。
3. **识别**（`lib/ocr/ocr_runtime.dart`）：原生库 `compoise_ocr` 用 PP-OCRv5 mobile 模型检测和识别文字，返回每行的文字、位置和置信度。图片逐张处理，可以取消。
4. **整理草稿**：
   - 先由 `lib/screenshot_import/gutter_scan.dart` 在像素里找出每行左侧的复选框，并判断它是否已勾选。复选框只从图像里判断，不会把识别出的 √ 之类的字符当成复选框。
   - 再由 `lib/screenshot_import/screenshot_adapter.dart` 把文字按行分组，判断每一行是什么（规则见下文“识别规则”）。
5. **校对**（`lib/import_preview/`）：识别出的任务默认选中，直接修改文字或取消不想导入的项，底部一键导入。默认使用当前任务板和普通新建任务的象限，可以在顶部修改。“更多”就地展开拆分、合并、父子关系、完成状态和日期备注；被跳过的文字放在“其他文字”里，展开后可以选入。重复项旁仅作简短提示，不阻止导入。
6. **导入**：确认后一次性写入任务库。取消或保存失败时任务库不变；保存失败后，校对结果会保留下来，可以重试。

## 识别规则

| 行的类型 | 判断方式 | 默认 |
| --- | --- | --- |
| 状态栏 | 位于截图顶部（宽度的 22% 以内），内容只有时间、电量百分比、信号或运营商之类的字样 | 跳过 |
| 任务 | 左侧有复选框 | 导入，复选框的勾选状态作为完成状态 |
| 标题 | 顶部区域的其他文字，或者左对齐但没有复选框的行 | 跳过 |
| 附加信息 | 没有复选框，文字在右半边（例如日期） | 跳过 |

- **纯文字清单**：如果整张截图里一个复选框都没有，就把它当作普通清单，左对齐的每一行都作为任务导入，默认选中。以 √、☐ 之类符号开头的行仍然跳过。
- 任务行右半边的日期文字会保留为原文，用户确认后才会作为备注保留，不会自动变成截止日期或提醒。
- 缩进的任务会挂到上面最近的一个父任务下。
- 被跳过的行仍然显示在校对页里，可以手动恢复。
- 识别内部的诊断信息不显示给用户，校对页只显示有明确说明的提示。

规则的回归测试：

- `test/screenshot_status_bar_test.dart`：真实中文截图，OCR 结果录制在 `test/fixtures/screenshots/`；
- `test/wp17_i3a_screenshot_adapter_test.dart`；
- `test/wp17_q2_structure_test.dart`。

## 模型

- 模型文件（检测模型、识别模型和字典）托管在本仓库的 `ocr-models-v1` Release 上，不随安装包分发。
- 第一次识别时，应用按顺序尝试几个下载地址，用 `lib/ocr/ocr_model_download.dart` 中固定的大小和 SHA-256 逐个校验，然后保存到应用数据目录下的 `ocr-models/v1/`。
- 校验失败的文件不会被使用。
- 更换模型时要发布新的 `ocr-models-vN` 并更新这些哈希，不要覆盖已有的文件。

## 原生库

- 源码在 `native/ocr/`（C++），依赖固定版本的 ncnn（`third_party/ncnn_pin.txt`）和 `stb_image.h`，只用 CPU 推理。
- 发行安装包里都带有编译好的库：
  - Android：`libcompoise_ocr.so`，包含 armeabi-v7a、arm64-v8a 和 x86_64；
  - Windows：`compoise_ocr.dll`；
  - Linux：`lib/libcompoise_ocr.so`。
- 编译方法见[开发指南](development.md#ocr-原生库)，第三方许可见 `native/ocr/THIRD_PARTY_OCR_NOTICES.md`。
- `native/ocr/tools/` 中是评测和设备驱动脚本，评测样本放在 `test/fixtures/ocr-evaluation/`。

## 隐私

- 原图和原始识别结果只在识别过程中存在于内存里，不写进任务库，也不写进日志。
- Android 会逐张建立受限的私有临时副本，识别后立即删除；取消、出错、退出或下次启动时，会清理这个模块留下的临时文件。
- 桌面端直接读取用户选择的文件，不会删除原图。
