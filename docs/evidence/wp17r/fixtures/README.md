# WP17 导入解析 · 候选测试夹具

`capture_cases.json` 是**契约提案 + 夹具**，不是可执行测试。本轮不改产品代码也不加测试，所以文件留在证据目录；如果它直接放进 `test/fixtures/`，就是一份没有任何测试引用的死数据。

## 内容

15 个用例（`WP17R-001` … `WP17R-015`），全部合成，覆盖：

- 单行、多行、空行/制表符/首尾空格（001、002）
- 空输入与纯空白不提交（003）
- 完成态标记：Markdown 复选框、厂商字形、白名单外标记不猜测（004–006）
- 自然语言日期不解析（007）
- 控制字符与 BOM 剥离（008）
- 超长截断（009）
- 附件失败路径：`file://` 拒绝、`content://` 未授权、非文本 MIME（010–012）
- `PROCESS_TEXT` 入口不回写（013）
- SAF 导出文本 + 持久化授权（014）
- 重复导入只提示不自动合并（015）

每个用例带 `basis` 字段：

| basis | 含义 |
|---|---|
| `existing` | 复刻仓库现有行为，实现时不得随意改动语义 |
| `proposed` | 本研究提出的新契约，WP17 落地前需确认 |
| `proposed, pending-probe` | 期望取决于真机分享形态，先跑 `../probe-protocol.md` 第 3 步再定 |

## 实现包怎么接

1. 把 `capture_cases.json` 移到 `test/fixtures/wp17_capture_cases.json`，与已有夹具同处（现有加载方式是按仓库根相对路径读取，见 `test/data_migration_test.dart:17-23`）。
2. 测试按 `cases` 迭代，`input` 喂解析入口、`expect.drafts` 断言草稿列表、`expect.warnings` 断言规则码、`expect.commits` 断言落库次数（0 时也必须显式断言不写库）。
3. `expect.warnings` 的码名是提案，实现时若与 `lib/l10n.dart` 现有命名风格冲突可改名，但**每条规则的判定语义不要改**：白名单外标记不猜完成态、日期不解析、附件读不到就如实失败。
4. 补两个本夹具没覆盖、但现有备份链路要求的路径：导入后 v2 导出往返一致；取消预览不产生任何写入。
